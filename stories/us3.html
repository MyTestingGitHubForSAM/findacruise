User story 3

Story 3 — Select a departure port

As a consumer, I want to select a departure port, so that I can search for cruises departing from a convenient location.

Dependencies: US1 · shared controls and panel state

Scope: Home Page component; illustrative data and existing design-system assumptions.

Why it matters

Consumers can choose a departure point that fits their travel plans.

Acceptance criteria

US3 · AC1#

AC1 — Display the port regions

Scenario: Open the Departure Port filter

Given the Find a Cruise component is displayed

When the consumer opens the Departure Port filter

Then the selector displays the five supported regions

And one region is presented as active

And the ports belonging to the active region are displayed

The supported regions are:

* North America.

* Caribbean.

* Europe.

* Australia.

* Asia.

US3 · AC2#

AC2 — Browse ports by region

Scenario: View ports from another region

Given the Departure Port filter is open

And "North America" is the active region

When the consumer selects "Europe"

Then "Europe" becomes the active region

And the ports assigned to Europe are displayed

And no departure port is selected as a result of changing regions

US3 · AC3#

AC3 — Select a departure port

Scenario: Select Seattle as the departure port

Given the Departure Port filter is open

And North America is the active region

When the consumer selects "Seattle, Washington"

Then "Seattle, Washington" becomes the selected departure port

And it replaces "Any Departure Port"

US3 · AC4#

AC4 — Change the departure port

Scenario: Replace a selected departure port

Given "Seattle, Washington" is selected

When the consumer selects "Miami, Florida"

Then "Miami, Florida" replaces "Seattle, Washington"

And only "Miami, Florida" remains selected

US3 · AC5#

AC5 — Open only one filter panel at a time

Scenario: Open this filter while another filter is open

Given another filter panel is open

When the consumer opens this filter

Then the previously open panel closes

And any existing selection in that filter remains unchanged

And only this filter panel remains open

Decisions & open questions

Temporary assumptions are not confirmed answers. Blocking decisions must be resolved before production Engineering.

Blocking questions and notes

Blocking Open

What is the authoritative source of departure ports and their region assignments?

Decision owner / domain
Product Owner / Data Owner / Technical Lead
Temporary assumption
An existing API or configuration supplies each port’s canonical ID, display name and region.
Source reasoning
Development cannot populate or group ports without an authoritative structure.
Blocking Open

Is Departure Port single-select or multi-select?

Decision owner / domain
Product Owner
Temporary assumption
Only one departure port may be selected.
Source reasoning
Cardinality affects the control and search contract.
Blocking Open

Does the selected destination restrict the available departure ports?

Decision owner / domain
Product Owner / Technical Lead
Temporary assumption
Selecting a destination does not dynamically restrict ports. Incompatible combinations may produce no results.
Source reasoning
Dynamic dependency would materially change state and data-loading behavior.

Non-blocking questions and notes

Non-blocking Open

Which region is initially active?

Decision owner / domain
Product Owner / UX Designer
Temporary assumption
North America is active by default, as shown in Visual Reference 4.
Source reasoning
This follows the supplied reference without introducing a new rule.
Non-blocking Open

How can the consumer return to Any Departure Port?

Decision owner / domain
Product Owner / UX Designer
Temporary assumption
The selector provides a clear action or unrestricted option.
Source reasoning
Consumers should be able to remove the restriction.

If an answer changes, review the affected acceptance criteria, interaction states and tests before implementation.
