User story 5

Story 5 — Search for cruises using selected filters

As a consumer, I want to search for cruises using my selected preferences, so that I can review sailings relevant to my destination, departure port and travel period.

Scope assumption

The existing search capability can receive the consumer’s selected search criteria and apply them on the Cruises page. The mechanism used to transfer those criteria is outside the scope of this exercise.

Dependencies: US1–US4 · completed criteria and external results capability

Scope: Product handoff to /cruises; prototype simulates applicable criteria only.

Why it matters

Consumers can continue exploring cruise options without re-entering their preferences.

Acceptance criteria

US5 · AC1#

AC1 — Search with all filters

Scenario: Search using destination, port and departure range

Given the consumer selected "Alaska"

And selected "Seattle, Washington"

And selected May 2027 through September 2027

When the consumer selects "Search Cruises"

Then the consumer is redirected to "/cruises"

And the destination filter is set to "Alaska"

And the departure port filter is set to "Seattle, Washington"

And the departure date filter is set to May 2027 through September 2027

And the displayed results conform to all three filters

US5 · AC2#

AC2 — Search with at least one selected filter

Scenario: Search using only a destination

Given the consumer selected “Alaska” as the destination

And the Departure Port filter displays “Any Departure Port”

And the Departure Date filter displays “Any Date”

When the consumer selects “Search Cruises”

Then the consumer is redirected to /cruises

And the displayed results are restricted to the selected destination

And the unselected filters do not restrict the results

US5 · AC3#

AC3 — Prevent a search without any selected criteria

Scenario: Attempt to search without selecting any filter

Given all three filters display their default “Any” values

When the consumer attempts to start the search

Then the search is not initiated

And the consumer is informed that at least one search criterion must be selected

Temporary behavior pending Product Owner confirmation of the minimum required selection

US5 · AC4#

AC4 — Display the applied search criteria

Scenario: Preserve search state on the results page

Given the consumer initiated a search from the Home Page

When the results page loads successfully

Then each criterion selected on the Home Page is displayed as selected

And the visible filter state corresponds to the criteria used to retrieve the results

US5 · AC5#

AC5 — Do not apply an unselected filter

Scenario: Search with an unselected destination

Given the Destination filter displays “Any Destination”

And the consumer has completed all required selections

When the consumer selects “Search Cruises”

Then the destination does not restrict the search results

Decisions & open questions

Temporary assumptions are not confirmed answers. Blocking decisions must be resolved before production Engineering.

Blocking questions and notes

Blocking Open

Can the existing Cruises page display and apply every search criterion selected in the Home Page component?

Decision owner / domain
Product Owner / Technical Lead
Temporary assumption
The existing Cruises page displays the selected criteria and applies them to the result set. The integration mechanism is outside the scope of this exercise.
Source reasoning
If this capability does not exist, additional results-page work enters the scope.
Blocking Open

What happens when valid criteria produce no matching cruises?

Decision owner / domain
Product Owner / UX Designer
Temporary assumption
The results page displays a zero-results state, preserves the filters and allows them to be changed.
Source reasoning
The system should not silently broaden the search.
Blocking Open

Which filters, if any, must be selected before the consumer can start a search?

Decision owner / domain
Product Owner
Temporary assumption
At least one filter must be selected. The three filters are individually optional, but an entirely unrestricted search cannot be submitted.
Source reasoning
The requirement does not define whether the initial state is searchable. This decision determines button enablement, validation behavior and the valid search scenarios.

Non-blocking questions and notes

Non-blocking Open

What loading behavior follows Search Cruises activation?

Decision owner / domain
UX Designer / Technical Lead
Temporary assumption
The action displays progress and prevents duplicate submission during navigation.
Source reasoning
Consumers need feedback while navigation is in progress.
Non-blocking Open

What happens if navigation fails?

Decision owner / domain
Product Owner / UX Designer
Temporary assumption
The current selections are preserved and an actionable retry message is displayed.
Source reasoning
A transient failure should not force the consumer to rebuild the search.

If an answer changes, review the affected acceptance criteria, interaction states and tests before implementation.
